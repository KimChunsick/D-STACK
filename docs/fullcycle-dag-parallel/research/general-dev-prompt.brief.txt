Research brief — system-prompt design for a dedicated general-purpose coding worker agent (delta research for Goal "DAG-parallel full-cycle pipeline")

Context:
A Claude Code user is adding an authored subagent definition ("general-dev") that will implement PR-sized, non-frontend coding tasks delegated by an orchestrator loop, sometimes several workers in parallel in isolated git worktrees. Each delegation prompt carries the concrete task brief (intent, files, constraints, repo conventions); the agent definition's standing system prompt must carry everything that should NOT be repeated per delegation: coding philosophy (plain, conventional, maintainable code; no speculative abstraction), strict test-driven discipline (Red-Green-Refactor), scope discipline (touch only the task's declared files), convention conformance to the target repo, and a reporting contract back to the orchestrator (what was done, test evidence, deviations, open questions — in English). An existing sibling agent ("frontend-dev") uses a structured XML-tagged prompt with a philosophy section, precedence rules, and axis-based principles, calibrated by the maintainer.

Research questions (both sides, current primary sources, 2024-2026):
A. What do current frontier-lab docs and guidance (Anthropic/Claude Code subagent docs, OpenAI/Codex agent guidance, Cursor rules guidance) recommend for coding-agent system prompts: structure, length, description fields for auto-routing, tool restrictions, examples vs principles?
B. What prompt content measurably improves code quality/maintainability from coding agents: explicit simplicity constraints, "match existing conventions" instructions, test-first mandates, forbidding unrequested refactors? Any published evaluations or ablations?
C. Prompt length vs instruction-following: evidence that very long rule lists degrade compliance (position effects, instruction dilution, rule conflicts), versus evidence that detailed structured prompts outperform short ones for agentic coding. Where is the practical sweet spot for a standing worker prompt?
D. Prior art worth imitating: published/open-source system prompts of real coding agents (SWE-agent, OpenHands, Aider conventions files, Claude Code agent examples, community "worker agent" definitions). What sections recur (role, philosophy, workflow, output contract, prohibitions)? What is deliberately left OUT and delegated to per-task context?
E. Parallel-worker specifics: guidance for agents operating in isolated worktrees — scope discipline (declared-file ownership), avoiding cross-cutting edits, reporting merge-relevant facts (new files, moved symbols, contract changes) back to the orchestrator.

Also collect evidence AGAINST: arguments that a dedicated standing prompt is unnecessary (per-task prompts + repo conventions suffice), that heavy principle lists cause checklist blindness or over-refusal, and that worker quality is dominated by task-brief quality rather than the agent definition.
