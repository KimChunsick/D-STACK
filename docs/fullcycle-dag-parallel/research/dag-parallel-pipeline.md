## Needed info

- The worktree-per-agent part of the plan matches current tooling direction: Claude Code documents parallel sessions and subagents with Git worktree isolation; Cursor has background agents and a 2026 `/multitask` worktree flow; OpenHands Agent Canvas advertises simultaneous agents isolated in git worktrees; Codex also documents isolated background tasks and worktree support. [S2][S3][S4][S5][S6][S7][S8]
- Git worktrees provide filesystem and branch checkout isolation, but they do not eliminate later integration conflicts. Git’s own model is “multiple working trees attached to the same repository,” with separate checkouts and administrative metadata; same-branch reuse is guarded, but same-file edits on different branches are still only discovered at merge/rebase time. [S1][S2]
- Each worktree needs its own local setup: dependencies, virtualenvs, dev servers, copied gitignored config, and test baselines. Claude Code explicitly notes gitignored files are absent unless copied via `.worktreeinclude`; Nx documents that parallel tasks can contend for shared resources such as ports and memory and supports `parallelism: false` for that reason. [S2][S12]
- DAG scheduling is mature prior art in CI/build/data systems: GitHub Actions and GitLab CI use `needs`; Nx builds a task graph and runs independent tasks concurrently; Airflow models tasks plus dependencies as a DAG; Prefect infers dataflow dependencies and supports explicit `wait_for`. [S9][S10][S11][S12][S13]
- Agent orchestration prior art supports both LLM-decided and code-decided flows. OpenAI’s Agents SDK distinguishes LLM orchestration from explicit code orchestration, and AutoGen documents deterministic sequential workflows and group-chat/state-flow patterns. For this pipeline, the stronger pattern is code-owned scheduling with LLMs producing validated proposals, not LLM-owned runtime control. [S14][S15]
- LLM-generated dependency graphs are a known weak point. A 2025 NeurIPS paper argues LLM-agent workflows often assume conditional independence between subtasks, but this assumption “frequently breaks”; its proposed mitigation is sequential verification under violated independence assumptions, not naive parallel fan-out. [S20]
- Repository-level coding often needs dependency analysis beyond prompt decomposition. Microsoft’s CodePlan frames repository-level coding as planning over interdependent code, using incremental dependency analysis and may-impact analysis; it reports 5/7 repositories passing validity checks versus 0/7 for baselines without planning. [S19]
- Review integrity needs explicit merge-base handling. GitHub changed stale-review behavior so approvals can be dismissed when a PR merge base changes; this is direct evidence that review approval against an old base is not equivalent to approval against a new integrated base. [S25]
- Per-task scoped review is insufficient to catch semantic merge conflicts. 2024 JSS work states modern merge tools can resolve text while missing semantic conflicts; another 2024 benchmark study shows real merge tools still have limitations on conflict detection/resolution. [S23][S24]
- Structured workflow definitions have strong support when the output is parsed or validated. OpenAI Structured Outputs, Claude structured outputs, and Gemini structured outputs all support schema-constrained JSON-style output; OpenAI reports constrained decoding achieved 100% schema adherence on its eval for `gpt-4o-2024-08-06`. [S16][S17][S18]
- Structure does not guarantee semantic correctness. OpenAI explicitly notes schema-constrained outputs can still contain wrong values, hit max-token failure modes, incur first-schema latency, and are incompatible with parallel function calls in that mode. [S16]
- Token-cost reduction from replacing a 250-line prose skill with YAML/JSON is plausible but not directly verified. The stronger verified claim is determinism at parser boundaries, not that models will interpret all structured instructions better or cheaper. [S16][S17][S18]

## Opposing views

- Opposing view: parallelism assumes independence, and LLM-planned independence is brittle. The strongest counter-source found is SeqCV: it argues dependency assumptions in LLM-agent graphs break during execution and that sequential consistency checks can outperform parallel pipelines when subtasks misalign. [S20]
- Opposing view: code review by isolated scoped diff can approve locally correct changes that fail once siblings merge. This is the same class of risk behind stale PR review dismissal and semantic merge conflict research: changed base plus clean textual merge does not imply reviewed integrated behavior. [S23][S24][S25]
- Opposing view: small task counts may not amortize coordination. METR’s 2025 RCT found experienced open-source developers were 19% slower with early-2025 AI tools, largely because prompting, waiting, and reviewing outweighed coding savings; METR’s 2026 update says late-2025 tools likely improved but measurement is confounded, especially when developers run multiple agents concurrently. [S26][S27]
- Opposing view: AI can increase activity without proportionally increasing shipped value. A 2026 study of over 100,000 GitHub developers reports autonomous agents increased commits substantially, but effects attenuated sharply at project and release levels, consistent with human bottlenecks in shipping. [S28]
- Opposing view: structured schemas add another maintenance surface. OpenAI and Gemini both document JSON Schema subsets; OpenAI documents first-schema latency and limitations; Anthropic’s 2025 prompt-engineering guidance says XML/structure is useful mainly when boundary ambiguity exists, not as universal ceremony. [S16][S18][S31]
- Opposing view: single-maintainer workflows may benefit more from shortening the slowest sequential gate than multiplying implementation workers. If adversarial reviews take 15-25 minutes, parallel implementation may just create a queue of review, merge, re-review, and E2E integration work. This exact 15-25 minute bottleneck was not independently verified, but the bottleneck logic is consistent with METR’s review/wait overhead findings and the shipping attenuation study. [S26][S28]

## For the goal

- The isolation mechanism is sound and already productized. Claude Code, Cursor, OpenHands, Conductor-style workflows, and Codex all converge on “one agent/session/task per isolated environment or worktree” as the practical pattern for concurrent coding. [S2][S3][S5][S6][S7][S8]
- DAG execution is a proven scheduler shape. GitLab explicitly describes `needs` as creating DAG-style pipelines that avoid waiting for unrelated stages; Nx runs independent task graph nodes in parallel while respecting prerequisites; Airflow separates task contents from dependency order. [S10][S11][S12]
- Runtime-structured decomposition has direct evidence for agentic coding workflows. A 2026 CAIS workshop paper reports runtime-controlled decomposition reduced retry costs versus monolithic and static decompositions by retrying only failed subtasks. This supports moving from a prose-only skill to an executable phase/gate schema. [S21]
- Structured outputs are a strong fit for gates, task manifests, dependency lists, file allowlists, and review bundle definitions. They let the orchestrator validate schema shape before acting, which is materially better than reinterpreting a long prose document each session. [S16][S17][S18]
- The current pipeline already has guardrails that can be adapted to parallelism: fail-closed file allowlists, void-on-change review rounds, per-task TDD, and final E2E gates. These are exactly the kinds of invariants needed to constrain fan-out and catch integration defects after fan-in. Supported mitigations from sources include stale-review dismissal, test-before/test-after worktree gates, and final merged-state testing. [S2][S12][S23][S25]
- Empirical coding-agent evidence is mixed but not hostile to the goal. Microsoft/INFORMS reports a 26.08% completed-task increase for AI coding assistants across 4,867 developers; PACIS 2026 reports Copilot Agent reduced mean task completion time by 61.7% in a 24-developer brownfield onboarding study, though correctness did not significantly improve. [S29][S30]
- Parallelism can clearly reduce wall-clock time in evaluation or embarrassingly parallel workloads. OpenHands reports 30x speedups for SWE-bench agent evaluation via remote sandboxing and parallel processing. That evidence transfers best to independent tasks/tests, not necessarily tightly coupled feature work. [S32]

## Against the goal

- The biggest concrete risk is false independence: tasks declared independent may touch the same files, APIs, schemas, lockfiles, migrations, routes, or tests. Git worktrees prevent live file corruption but push these conflicts to merge time. [S1][S2][S23][S24]
- Semantic conflicts are more dangerous than textual conflicts because they can merge cleanly. 2024 semantic-merge research reports that text/structured merge can miss behavior-level conflicts; generated tests detected only a subset of known semantic conflicts, so final E2E is necessary but not complete protection. [S23]
- Per-task adversarial review becomes weaker under sibling concurrency unless the reviewed base is pinned and later revalidated after merge. A reviewer scoped to task A cannot see that task B changed the contract A depends on. GitHub’s stale-approval rule is a useful analog: changed merge base can invalidate prior approval. [S25]
- LLM dependency planning should not be trusted as the only scheduler input. The better pattern is: LLM proposes dependencies and file ownership; deterministic checks reject overlapping file sets, shared contract edits, migration/lockfile overlap, or changed public interfaces; integration review handles the rest. [S19][S20][S21]
- Wall-clock savings for 2-6 tasks are unverified and may disappear. Existing measured evidence is either broader AI productivity, benchmark-scale parallel evaluation, or vendor/product documentation. I found no primary study measuring “single maintainer, 2-6 PR-sized LLM-agent tasks, worktree DAG, adversarial review loop” end-to-end. [S26][S27][S28][S32]
- Structured schemas can make the system more deterministic but also more rigid. If the 250-line prose skill contains nuanced judgment, a schema-only rewrite can lose context unless it keeps short prose annotations and explicit escape hatches for human decisions. [S16][S31]
- A safer alternative is staged adoption: first convert the prose pipeline into a typed state/gate schema while keeping sequential execution; then add parallelism only for tasks passing conservative disjointness checks; then require final merged integration review/E2E before milestone closure. This is better supported by the evidence than jumping directly to broad parallel fan-out. [S10][S11][S19][S20][S25]

## Unverified

- I could not verify any primary measurement of end-to-end wall-clock reduction for 2-6 PR-sized LLM coding tasks inside a single-maintainer worktree DAG with adversarial review and consensus loops.
- I could not verify actual merge-conflict or semantic-conflict rates for LLM-agent sibling branches specifically; available evidence is from general software merging, vendor guidance, and anecdotal agent-worktree practice.
- I could not verify that converting a long prose Claude Code skill into YAML/JSON measurably reduces token cost or interpretation drift in Claude Code specifically.
- I could not verify that Claude Code, Cursor, Codex, or OpenHands publish quantitative success/failure rates for concurrent worktree agents on real user repositories.
- I could not verify the maintainer’s claimed 15-25 minute adversarial-review bottleneck externally; it should be measured locally before optimizing implementation parallelism around it.
