Goal: In Claude Code, define a dedicated "frontend-dev" custom subagent (agents/*.md) that owns ALL frontend implementation work (React/TypeScript components, hooks, styles, frontend utils), and mechanically enforce that the main agent loop never edits frontend files directly — it must delegate to this subagent.

Research questions:

1. Claude Code custom subagents, current state (2026): file location (~/.claude/agents/*.md vs .claude/agents/), frontmatter schema (name, description, tools, model, any newer fields), how auto-delegation is triggered, how reliable "MUST BE USED"/"use PROACTIVELY" description phrasing is in practice, and how the main agent passes context to the subagent.

2. Mechanical enforcement: can a PreToolUse hook distinguish a tool call made by the MAIN agent from one made by a SUBAGENT? What fields does the hook stdin JSON carry today (session_id, transcript_path, permission_mode, anything agent-identifying like agent name/type)? Is there any documented or community-verified way (env vars, transcript path shape, CLAUDE_* variables, hook config scoped per agent, "disableAllHooks" or agent-level hook overrides) to write a hook that blocks Write/Edit on frontend file patterns in the main loop but allows them inside a specific subagent? Cite primary docs and real-world examples (GitHub issues, changelogs).

3. Do PreToolUse hooks fire for subagent tool calls at all? Any per-agent hooks support in agent frontmatter? Any recent changelog entries about hooks + agents interaction?

4. Alternatives and their tradeoffs: permissions deny rules, CLAUDE.md instruction-only routing, PreToolUse matcher on file paths with an allow-token handshake (e.g., subagent sets a marker file/env), Task-tool-based routing. Evidence FOR hard enforcement (consistency, guaranteed standards) and AGAINST it (false positives on mixed files, deadlock if the subagent itself is blocked by the same hook, added latency, brittleness across Claude Code versions).

5. Failure modes to design around: hook blocking the subagent too, markdown/docs files containing frontend code snippets, renames/deletes via Bash bypassing Write/Edit hooks, and how strict the file-pattern heuristic should be (extensions like .tsx/.jsx/.css/.scss vs path-based).

Context: single-user personal setup, macOS, Claude Code CLI latest, settings.json already uses UserPromptSubmit and Stop hooks. The subagent definition content itself is already authored; this research is ONLY about the subagent packaging + enforcement mechanics, not frontend coding standards.
