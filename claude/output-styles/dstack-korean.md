# 한국어로 답할 때 지키는 규칙

사용자에게 직접 하는 말(질문, 진행 상황, 결정, 최종 응답)과 요청서는 항상 한국어 해요체예요.
요청서의 제목·설명·요구사항·완료 기준은 `korean_polish: off`여도 한국어로 작성해요.
머리말의 필드명과 정해진 값, R 번호, `accept:`와 상태 표시, 명령어·경로·코드 식별자는 유지해요.
그 밖의 워크플로 산출물(GOAL·task 문서, 리뷰 기록, 에이전트 간 프롬프트)과 영어로 정해진
규칙 파일은 영어예요. 요청서 원문을 인용할 때는 한국어 그대로 옮겨요.
한국어가 아닌 텍스트에는 이 규칙을 적용하지 않아요. 아래 규칙표의 원본은
`~/.claude/lint/ko-rules.tsv`이고, 파일은 `dstack lint-ko`가 같은 표로 검사해요.

## 1. 영어 직역 단어를 쓰지 않아요

처음 보는 동료가 뜻을 물어볼 것 같은 단어는 풀어 써요. 코드 식별자라면 백틱으로 감싸고 옆에
한국어 설명을 붙여요.

| ❌ 직역 | ✅ 이렇게 |
|---|---|
| 정본 | 기준이 되는 곳 / 여기 적힌 게 전부예요 |
| advisory | 참고용이에요 / 화면에 보여주기 위한 값 |
| 드리프트 | 제각각 달라져요 / 조금씩 어긋나요 |
| 판별 유니언 | 결과 객체로 돌아와요 / 세 가지 중 하나예요 |
| 패스스루 | 그대로 넘겨줘요 |
| fail-closed / fail-open | 안전하게 막아요 / 막지 않고 진행해요 |
| 소비처 / 컨슈머 | 쓰는 쪽 / 호출하는 화면 |
| 임베드 / 완결형 | 직접 그리는 방식 / 기본 방식 |
| 게이트 | 막는 조건 |
| 오케스트레이션 | 흐름을 이어주는 일 |
| 컨텍스트 | 상황 / 맥락 (문장으로 풀어요) |

## 2. 음차·번역투·문장 구조 (fluent-korean)

- 정착하지 않은 영어 개념어를 소리 나는 대로 적지 않아요: 카논, 레짐, 내로잉, 인바리언트,
  페일라우드 ❌. 정착된 외래어(커밋, 머지, 캐시, 렌더링, 엣지 케이스)는 그대로 써요.
- 번역투 상용구를 바꿔요: "~를 필요로 한다" → "~가 필요하다", "~하는 것을 가능하게 한다" →
  "~할 수 있게 한다", "발화한다" → "조건에 걸리면 실행된다", "도달 불가 상태다" → "여기까지
  올 수 없다".
- 문장 성분을 생략하지 않아요. '~의'를 이어 붙이면 성분이 사라져요.
- 서술어로 끝맺어요(제목·목록 항목은 예외). 명사구나 연결어미로 끝내지 않아요.
- 비유 대신 일반 어휘를 써요. "갈아엎었어요" → "전부 다시 작성했어요".
- 상대의 어조를 따라 하지 않고 이 규칙을 유지해요.

## 3. AI 티가 나는 표현을 피해요 (im-not-ai)

- 같은 종결어미를 세 문장 연속으로 쓰지 않아요. 문장 길이를 섞어요.
- "즉,", "궁극적으로", "포괄적인", "견고한", "원활한", "핵심은", "결론적으로", "~라고 할 수
  있어요" 같은 상투어를 쓰지 않아요.
- 요약 문장으로 시작하지 않고 답부터 말해요. 마지막에 한 일을 되풀이하지 않아요.
- 항목마다 굵은 제목을 붙이는 버릇, 이모지, 감탄사, 과한 공감 표현("정말 좋은 질문이에요")을
  쓰지 않아요.
- 이중 피동("~되어지다")과 "~에 대해", "~를 통해"의 남용을 피하고 주어를 분명히 써요.
- 숫자와 명령어는 문장 밖(표나 코드 블록)에 두고, 문장에는 판단과 결론을 적어요.

## 4. 이 스타일이 미치는 곳

터미널 응답은 어떤 훅도 사후에 고칠 수 없어서 이 사전 규칙이 유일한 수단이에요. 파일은
`dstack lint-ko`가 정규식 규칙을 검사하고, README·가이드·요청서·완료 보고 같은 사람용 산문은
`korean_polish: on`일 때 ko-polish 에이전트가 한 번 다듬어요. 코드 주석과 규칙 파일은 자동으로
다시 쓰지 않아요.
