# dstack-develop — Milestone loop, waves, workers, review calls

This skill runs in the **main session**. The main session is the only writer of `.dstack/`
(R36, R66): workers implement and commit, the main session records. Every checkbox and every
pass/fail comes from a `dstack` verb — the agent never ticks a box (§3-1).

## 1. Hierarchy (R60)

| Level | What it is | Where it lives |
|---|---|---|
| Project | the repository | `.dstack/project/PROJECT.md` |
| Goal | one approved request | `.dstack/runs/<id>/request.md` |
| Milestone | one turn of the five-stage loop, sized to **3–6 Plans** | `plan.json` → `ROADMAP.md` |
| Plan | the concurrency unit and the review unit; one worker owns it whole | `plan.json` plans[] |
| Task | one finished piece of work inside a Plan = **one commit** | `plan.json` tasks[] |

GSD's definitions, kept verbatim (`docs/explanation/the-phase-loop.md`):

> "Each `PLAN.md` describes a bounded unit of work: the files to touch, the specific changes
> to make, the acceptance criteria that define done."

> "Each commit corresponds to a completed task in a plan."

A Task is never split further and never carries internal commits (R60).

## 2. The five-stage loop, once per Milestone (R61)

GSD runs discuss → plan → execute → verify → ship per *phase*; v2 has no phase layer, so the
unit is the **Milestone** and the fresh-context unit stays the Plan.

| Stage | What the main session does | Ends when |
|---|---|---|
| Discuss | interview round for this Milestone only, budget from R51 (first Milestone 2 rounds × 5 questions, later 1 × 3); `dstack ask add` / `dstack ask answer` / `dstack ask assume`, `dstack decision add` | `dstack ask list` shows 0 open |
| Plan | `dstack milestone add`, `dstack plan add`, `dstack task add`; then `dstack plan render` | render shows 3–6 Plans, every live R covered |
| Execute | the wave loop of §5 | no Plan of this Milestone is `pending`/`in-progress` |
| Verify | the milestone's e2e pass — one `e2e-runner` over every open case of every Plan, recorded per artifact (verify §4–§5, §7) — then `dstack check coverage`, `dstack check decisions`, `dstack verify` | all three exit 0 |
| Wrap-up | `dstack review --scope milestone`, close finished quick items, report to the user | the ledger pass seals |

**GSD verification warns; here it blocks.** GSD: "A phase is not done because execution
finished without errors." In v2 the same three checks are exit codes the Stop hook reads, so a
Milestone cannot be called done while any of them is non-zero.

Milestone sizing follows GSD's phase-scope rule ("When in doubt, split"): a Milestone that
does not fit in 3–6 Plans is two Milestones — add the second with `dstack milestone add`.

## 4. What the request switches on (R71)

No stage runs unconditionally (§3-3). Read the frontmatter of `request.md`; a stage that is
off is recorded, never silently dropped:
`dstack decision add "<stage> skipped: <reason>" --affects R07,R09`.

| Field | On → | Off → record |
|---|---|---|
| `unit_tests: on` | Red/Green/Refactor inside each Task (§4.1), `unit-test` skill | `skipped: unit_tests=off` |
| `review: on\|off` | rounds and axes of `codex-review`; the per-R covered/partial/absent verdict never turns off (R69) | `skipped: review=off (verdict still required)` |
| `e2e: capture\|cli\|none` | which evidence kind the milestone's e2e cases take — run once per milestone, never per Plan (verify §1) | `skipped: e2e=none` |
| `korean_polish: on` | `ko-polish` on human-facing prose only | `skipped: korean_polish=off` |
| `codex_effort` | review and research use fixed `model_reasoning_effort=high`; legacy values remain readable | — |

### 4.1 Red/Green/Refactor (R62)

For `work_type` in `web-ui | http-api | cli | library`: Red, Green and Refactor all happen
**inside one Task and produce one commit**. The Red evidence is not a commit — it is the
failing test output, saved by the worker to `<artifact-dir>/R<NN>-red.txt` and recorded by the
main session:

```
dstack evidence add --r R07 --case c-test --kind test \
  --artifact .dstack/runs/<id>/artifacts/P3/R07-red.txt \
  --produced-by "npm test -- R07" --note "red before green"
```

`docs-writing` has no Red/Green/Refactor: each R row's acceptance criterion is checked one by
one and the check itself is the evidence row.

## 5. The wave loop (R66, R38)

Plans are the concurrency unit; overlap is decided on declared `files`, not on guesswork.
GSD `docs/CONFIGURATION.md`: `parallelization.max_concurrent_agents` default `3`,
`workflow.use_worktrees` default `true`. v2 keeps both, but **the CLI creates the worktree**
(R36) and only the main session writes `STATE.md` and the ledger, under the CLI's lock.

```
1. dstack next --max 3
     → ready set, overlapping pairs with reasons, the cap, the schedulable subset,
       and cross-run overlap warnings (R38: other runs warn, they do not block)
2. for each schedulable plan:
     dstack plan start P3 --worktree ../wt-<run>-P3
     → the CLI runs `git worktree add` itself and records the path in plan.json
3. spawn one worker per plan — ALL Agent calls in ONE message so they run as a wave.
     model explicit (R25); brief = §6 template; nothing else in the worker's context.
4. wait for the wave; each worker's first line is its `dstack run verify` output.
5. per returned worker: run the checklist of §7, in order.
6. dstack next --max 3   → next wave. Repeat until the Milestone has no pending plan.
```

**Isolation ban (R36).** Never use Claude Code's own worktree isolation: no `--worktree` flag
on the Agent tool, no `EnterWorktree`, no `isolation: worktree` in agent frontmatter, no
`worktree.baseRef` setting, no WorktreeCreate hook. That isolation blocks writes to the main
checkout and cannot be turned off, which contradicts R32's store location.

Tasks inside one Plan run sequentially in that one worktree. Workers commit with
`git commit --no-verify` (GSD `docs/CONFIGURATION.md`: "executor agents commit with
`--no-verify` to avoid build lock contention … STATE.md writes are protected by file-level
locking"); the lint that a pre-commit hook would do is already done by the pre-write hook and
`dstack lint-ko --changed` at Stop (R93).

### Delegation defaults (R25) — model is always explicit

| Work | Agent | Model |
|---|---|---|
| Frontend code: components, hooks, styles, markup, frontend utilities, frontend tests, stories, frontend build config | `frontend-dev` | opus |
| Everything else: backend, CLI, scripts, config, docs and their tests | `general-dev` | opus |
| Recon before the interview | `recon` | sonnet |
| Running a verification profile | `e2e-runner` | sonnet |
| Korean polish of human-facing prose | `ko-polish` | sonnet |
| Code review, external research | Codex `gpt-6-astra` | `model_reasoning_effort=high` for every call |

A Plan that touches frontend code goes to `frontend-dev` even inside a full-stack Plan; split
the Plan when both sides move together and give each brief the other side's contract.

## 6. Worker brief template (R68)

Copy this block, fill every section, send nothing else. The worker starts empty-handed.

```
# Plan P3 — <slug>   (run <run-id>, milestone M2)

## Project
<3–5 lines from .dstack/project/PROJECT.md, including the Verification policy block>

## Milestone context
<the Milestone goal in one sentence + the decisions of this Milestone's discuss stage>

## Recon (relevant rows only)
<the rows of recon.md whose "R" column intersects this Plan's covers, plus the
 first line: team style resolution>

## The Plan
files:  <declared files, verbatim from plan.json>
deps:   <plan deps, all already done>
tasks:  T7 <slug> covers R07 files … | T8 <slug> covers R09 files …
acceptance: <what "done" means for this Plan>

## R rows you cover (verbatim from request.md — do not paraphrase)
- [ ] **R07** … — accept: …
- [ ] **R09** … — accept: …

## D rows those R rows point to (verbatim from decisions.md)
| D-04 | … | R07 | answered |

## STATE summary
current_plan: P3 | ready: P4 | in_progress: P3, P5 | blocked: P6 | last_commit: <sha>

## Where you work
worktree: <abs path>   branch: <branch>   base HEAD: <sha>
artifact dir: .dstack/runs/<run-id>/artifacts/P3/   ← the only path under .dstack/ you may write
First action: run `dstack run verify` and report its output. If pwd, common-dir, branch or
HEAD differ from the three lines above, stop and report "delegation void: location mismatch".

## Rules
- One Task = one commit, `git commit --no-verify`, Korean 해요체 message, no AI trailer.
- unit_tests: <on|off>. When on: Red (failing output → artifact dir) → Green → Refactor,
  all inside one Task.
- Korean text follows `~/.claude/output-styles/dstack-korean.md`; read it before the first
  Korean sentence. (Output styles do not reach subagents — R92.)
- Friction with `dstack` itself — a detour, a refusal that stopped you, wording that cost you
  time — is filed with `dstack issue new` (every value in single quotes, or the shell expands
  the incident text) and never by hand; an idea you merely had is not filed.
- Report every R id above exactly once as `R<NN>: satisfied|unsatisfied|blocked — <why>`.
  An R you could not satisfy is reported, never quietly dropped.
```

## 7. After each worker returns — the main session checklist

Run in this order. Every step is a CLI verb; nothing here is a judgment call.

| # | Command | Why |
|---|---|---|
| 1 | read the `run verify` lines of the report | a location mismatch voids the delegation (R36); re-run the Plan, do not accept its commits |
| 2 | `dstack worker report --plan P3 --from <report-file>` | prints `reported: N / unreported: M (R…)`; writes the M rows to the ledger as `unreported` (R68) |
| 3 | `dstack evidence add --r R07 --case c-test --kind test --artifact <path> --produced-by "<cmd>"` (one per test artifact the worker produced) | the ledger's only writer is the main session (R104); the Red output exists only now. E2E cases are not run here — they wait for the milestone close (verify §1) |
| 4 | `dstack task done T7 --commit <sha>` (one per task in the report) | records the commit that is the Task |
| 5 | `dstack plan done P3` | refreshes readiness; regenerates ROADMAP.md and STATE.md under the lock |
| 6 | `dstack review --scope plan --plan P3` then the `codex-review` skill on the bundle | review is per Plan and unconditional (R69) |
| 7 | `dstack review seal --from <codex-output> --scope plan --id P3` | one sealed `codex-review-<NNN>.md` per round; sealed rounds are never edited |

If step 2 reports `unreported: M` with M > 0, those R ids sit in the ledger as `unreported`
and `dstack check coverage` keeps failing until each one gets evidence or a follow-up Plan.

Nothing in this checklist waits on the issues a worker filed; `dstack issue list` reads them
back whenever you want to look.

Korean progress line to the user, e.g. "P3 워커가 R07·R09를 보고했고 미보고는 없어요.
리뷰 번들을 만들어서 Codex 리뷰로 넘겼어요."

## 8. Review calls (R69, R70) and long runs (R98)

- **Per Plan** — `dstack review --scope plan --plan P3` builds the bundle (frozen REQUEST
  section + the Plan's covers + the diff of allowed files) and refuses to emit one that fails
  `dstack check review-bundle`. The verdict is per R: `covered | partial | absent`. One
  `absent` blocks a positive seal; `review: off` shrinks rounds and axes, never the verdict.
- **At Milestone / Goal close** — `dstack review --scope milestone --milestone M2` makes the
  ledger-pass bundle: only the open items of `findings.md` and integration behaviour, with the
  prompt contracting the reviewer not to open new-scope findings. Oversize → split per Plan.
- The Codex call itself belongs to `codex-review`. It is a long external run, so it goes in
  ONE background Bash call and the turn ends; the completion notification resumes the session:

```
dstack exec <label> -- codex exec --ignore-user-config -m gpt-6-astra -c model_reasoning_effort=high --sandbox read-only -o <out-file> "$(cat <bundle-path>)"
```

Keep `high` for every call, including quick tasks and the final sealing review. Legacy
request values do not override the fixed effort.

## 9. Resume, insert, remove (R61(5), R67)

| Situation | Commands |
|---|---|
| Session lost / `/clear` / new terminal | `dstack run adopt` (stale owner auto-adopts; `--force` otherwise), then read `STATE.md` for `current_plan`, `ready`, `in_progress`, `blocked`, `last_commit`, then `dstack next` |
| Urgent work inside the Goal | `dstack plan insert --after P3` (decimal `P3.1`) — refused while the dependent subtree has an in-progress Plan; never `quick` (R99) |
| A Plan is wrong and not started | `dstack plan edit` / `dstack plan remove` |
| Scope grew past the Milestone | `dstack milestone add <slug> --after M2` |

## 10. Closing a Milestone and the Goal

1. The milestone's e2e pass (verify §7 step 3): one runner over every open case of every Plan in
   the milestone, one `dstack evidence add` per artifact. A failed case becomes a decimal Plan
   (`dstack plan insert --after P<n>`) with its own review round; the milestone waits.
2. `dstack check coverage`, `dstack check decisions`, `dstack verify` — all exit 0.
3. `dstack review --scope milestone --milestone M2` → ledger pass → seal.
4. Goal close records no new evidence (every case ran at its milestone): `dstack verify` also
   checks branch containment (R38). If the Goal branch does not contain the base branch HEAD it
   refuses with "rebase first". After the rebase, re-run the ledger pass (step 3) for every
   Plan whose files had conflicts, then close.
5. `dstack report` — R table with computed status; `UNMET` exits 1, only `ABSTAIN`/`BLOCKED`
   exits 2. Accept each one deliberately: `dstack verify --accept-abstain R05 --why "<why>"`.
6. `dstack run close`.

Korean wrap-up line, e.g. "M2는 Plan 4개가 전부 done이고 검사 세 개가 통과했어요. 남은
ABSTAIN은 R05 하나예요 — 사유를 확인해 주시면 받고 Goal을 닫을게요."
